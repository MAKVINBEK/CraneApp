



# Миграция Backend v2

`backend-v2` — это новый backend, который заменит существующий. Он намеренно изолирован от устаревшего Node.js gateway до момента полного перехода на новую систему в продакшене.

## Реализованный функциональный срез (vertical slice)

- `edge` — публичная маршрутизация `/api/v2` и единая политика HTTP-ответов.
- `auth` — регистрация и вход пользователей с владением схемой PostgreSQL `auth`.
- `user` — профиль пользователя, поиск пользователей, настройки, параметры приватности и управление заблокированными пользователями.
- `chat` — личные и групповые чаты, участники, а также пользовательское состояние (закрепление, архивирование, статус прочтения).
- `crypto-rust` — хеширование паролей с использованием Argon2id, выпуск подписанных краткоживущих access token, envelope-шифрование AES-256-GCM и валидация MLS-артефактов на этапе миграции.
- Контракты OpenAPI v2 и Protobuf.
- Базовая инфраструктура Docker Compose и Kubernetes.

В настоящее время внутреннее взаимодействие с криптографическим сервисом осуществляется по HTTP и изолировано с помощью Kubernetes NetworkPolicy. Перед использованием в продакшене его необходимо заменить на автоматически сгенерированные gRPC-клиенты с использованием mTLS. Исходным контрактом для этого этапа является `contracts/proto/crypto.proto`.

## Локальный запуск

1. Запустите PostgreSQL, NATS, Redis, MinIO, сервисы `crypto`, `auth` и `edge`:

   ```bash
   docker compose -f infrastructure/docker/docker-compose.v2.yml up --build
   ```

2. Примените все SQL-файлы из каталога `backend-v2/migrations` к базе данных PostgreSQL.

3. Используйте публичный API по адресу:

   ```
   http://localhost:8080/api/v2
   ```

Перед переключением на новую систему выполните команду:

```bash
make migrate-legacy-dry-run
```

из каталога `backend-v2`.

Команда запускает миграцию в транзакции с уровнем изоляции **Serializable**, проверяет количество перенесённых записей и всегда выполняет **rollback**, если явно не передан флаг `--apply`.

## Обязательный порядок миграции

1. Реализовать сервисы сообщений, realtime-обновлений, звонков, медиа и поддержки/администрирования.
2. Добавить Transactional Outbox и обработчики событий на базе NATS JetStream.
3. Реализовать инструмент миграции данных из legacy-системы в Backend v2 с сохранением существующих UUID.
4. Сгенерировать React API-клиент на основе спецификации `contracts/openapi/api-v2.yaml`.
5. Провести полные репетиции миграции и нагрузочное тестирование перед включением режима технического обслуживания.

До тех пор, пока каждая функция, используемая клиентскими приложениями, не получит реализацию в API v2 и не будет полностью выполнен контрольный список миграции (cutover checklist), **Node.js backend остаётся основным источником истины (source of truth) для продакшена**.
